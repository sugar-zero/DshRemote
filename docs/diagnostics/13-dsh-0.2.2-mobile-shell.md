# 13 — DSH 0.2.2 手机壳适配：侧栏抽屉与设置弹窗交回 DSH 原生实现

快照：2026-11-16 · 适配版本：**DSH 0.2.2（桌面端 0.2.2-rc.2）** · 涉及：`dsh-remoteApp/src/lib/mobileWebShell.ts`、
`dsh-remoteApp/scripts/check-injected-shell.mjs`

## 1. 现象

主机 DSH 升到 0.2.2 后，手机 App（注入手机壳）出现两处回归：

1. 左上角多出一个「左侧栏」按钮；点开后画面变暗，但**抽屉里什么都没有**（只剩一行若隐若现的
   「工作区」和设置按钮），点哪都没反应；
2. 设置弹窗顶部同时出现手机壳的「返回」和 DSH 原生的「关闭 ×」，两者挤在同一行；打开分区菜单时，
   所有分区**横向排成一排**，内容区被挤窄。

## 2. 根因

DSH 0.2.2 的 Web 客户端新增了两套**窄屏原生实现**，与手机壳里按 0.2.1 写的自绘层直接冲突：

| DSH 0.2.2 新增 | 位置（客户端 bundle） | 与手机壳的冲突 |
|---|---|---|
| 窄屏侧栏抽屉：`frame[data-sidebar-drawer]`，`_sidebarCol` 改绝对定位 + `translate(-100%)`，配套 `drawerMask`，左上角原生入口 `[data-sidebar-opener]`（`shell.leading` 槽） | `dsh-client-ui-layout`、`dsh-client-ui-sidebar` | 壳仍给 `_sidebarCol` 写 `position: fixed !important` + 常驻 `opacity: 0; pointer-events: none`，只有自绘的 `html.dsh-mobile-drawer-open` 才恢复；原生入口不会加这个类 → 抽屉打开时 DSH 的 `visibility/transform` 生效、但透明度和点击穿透仍是壳设的 0/none |
| 设置弹窗窄屏布局：`@media (width<=767px)` 下整屏 `panel` + 顶部标题/关闭 + **横向**分区条（`navList{flex-direction:row}`） | `dsh-client-ui-settings-general` | 壳注入的手机栏插进了新 DOM 的 header 区（与原生 × 同排）；壳把 nav 变成抽屉后，原生窄屏规则仍让分区横排 |

## 3. 修复

原则：**DSH 已经自带窄屏实现的，壳不再自绘**。

- 删除自绘侧栏抽屉：`_sidebarCol` 的 fixed/transform/opacity/pointer-events 规则、遮罩、`dsh-mobile-drawer-open`
  状态机、鲸鱼入口、边缘手势、点击外部收起逻辑；
- 删除设置弹窗手机壳：注入手机栏、分区抽屉、抽屉遮罩、`dsh-settings-mobile` 状态类、设置页手势、
  用于补装的 MutationObserver；
- 保留壳的其余职责：viewport 锁定、侧栏 safe-area 底部留白、窄屏右栏全屏处理、外链交给 App 内嵌浏览器、
  隐藏「在主机本机打开 / 添加工作区」等主机本机控件。

## 4. 适配版本与验证

| 项 | 值 |
|---|---|
| 目标 DSH 版本 | **0.2.2 及以上**（0.2.2 起才有原生窄屏抽屉与设置布局）；**不再兼容 0.2.1 及更早**（旧版没有移动端侧栏入口） |
| 实测版本 | 桌面端 `0.2.2-rc.2`（`dsh-client-ui-layout` / `dsh-client-ui-sidebar` / `dsh-client-ui-settings-general` 均为该版本） |
| 静态检查 | `npx tsc --noEmit`、`npm run check:native`、`npm run check:shell` 全过；`check:shell` 新增两条护栏（样式表不得出现 `_sidebarCol` 规则；侧栏 `position/opacity/pointer-events` 保持原生值），并删除依赖自绘设置壳的旧用例 |
| 真机 | iPhone 17 Pro Max / iOS 27.0；群体版 App 0.2.2（build 25）安装后由用户验收通过（2026-11-16）：侧栏抽屉可开、会话列表可见可点，设置页为 DSH 原生窄屏布局（标题 + 关闭 × + 横向分区条） |

## 5. 以后升级 DSH 时先看这里

- 判断依据是客户端 bundle 里的 `data-sidebar-drawer`、`[data-sidebar-opener]`、`settings-general` 的
  `@media (width<=767px)` 段；这些存在时，壳**不要**再覆盖 `_sidebarCol` 或往 `[data-shortcut-modal="settings"]`
  里插任何东西。
- 壳自己维护的检查脚本 `check-injected-shell.mjs` 里有对应的回归护栏，改 DSH 版本后先跑 `npm run check:shell`。
